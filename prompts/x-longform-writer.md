# prompts/x-longform-writer.md — X長文記事 生成プロンプト

> スキル名：`actualworks-x-writer`
> 用途：ACTUAL WORKS X長文記事の生成
> 最終更新：2026-06-29

---

## このスキルの目的

読者の**認識を変える**X長文記事を生成する。
「なぜやるか・何が本質か・どう考えるか」を渡し、共感・納得・理解を積み上げる。
手順・ツール・操作方法は書かない（それはnoteの役割）。

---

## 入力（必須）

```
テーマ       ：記事で扱う問題・概念・考え方
狙い         ：読者にどんな認識変容を起こしたいか
対象読者層   ：A（未着手）/ B（未設計）/ C（未仕組み化）
一次情報     ：実体験・失敗談・気づきのエピソード（任意だが強く推奨）
```

---

## アンチ・マンネリ 3エンジン（TEXTUAL_IDENTITY_SPEC_v3.0 準拠）

毎回、以下の順番で実行する。フックや語彙を選ぶより**先**に必ずやること。

### エンジン1：内容ドリブン選択
書く前に「この内容の本当の感情は何か」を1語で特定する。
感情タグ例：驚き／悔しさ／怒り／興奮／困惑／発見／自省／呆れ／焦り／安堵
フックはその感情から逆算して選ぶ。バンクから機械的に拾わない。

### エンジン2：ローテーション・ロック
`operations/article-log.md` を確認し、以下を直近で使ったものは今回禁止にする。

| 要素 | ロック期間 |
|---|---|
| フックの「型」 | 直近3本 |
| フックの具体フレーズ | 直近5本 |
| クローザーの型 | 直近3本 |
| 積極語彙の同一単語 | 直近2本 |
| リズムの緩急の置き場所 | 直近2本 |

### エンジン3：今日の縛り（ダイス）
投稿番号を7で割った余りで1つ選ぶ。長文は余りと余り+3（7超は-7）の2つを引く。

| 余り | 今日の縛り |
|---|---|
| 0 | フックに感嘆符（！）・三点リーダー（…）を一切使わないで指を止めさせる |
| 1 | 本文に具体的な数字を3つ以上埋め込む（時間・回数・金額・%のどれか） |
| 2 | 自虐・失敗談を必ず1回入れる（1回だけ。多用禁止） |
| 3 | 体言止めを1回だけ使ってリズムを切る |
| 4 | 一番言いたい結論をあえて中盤に置く（冒頭・末尾に置かない） |
| 5 | 問いかけ→自分で即答の形を1セット入れる |
| 6 | 一文だけ極端に短く（5〜10字）して落差を作る |

## 生成手順

### Step 1. テーマを「認識の問題」として定義する

- 読者が今どう思っているか（誤解・思い込み）を特定する
- それに対して「本当はこうだ」という転換点を一文で言える状態にする
- 転換点が言えない場合は、テーマを絞り直す

### Step 2. 構成を組む

```
1. 違和感・問題提起
   └ 読者がうなずける出発点。「あるある」から入る

2. よくある誤解・思い込み
   └ 読者が今やっていること・信じていることを言語化する
   └ 批判せず「自分もそうだった」トーンで

3. 本質の問い
   └ 「でも、本当の問題はここじゃなかったんですよね」
   └ 一文で核心をつく

4. 視点の転換・再定義
   └ 考え方の枠組みを変える
   └ 事例・比喩・失敗談で肉付けする

5. 読者が今日から変えられる「認識」
   └ 行動指示ではなく「こう考えると楽になる」「こう見えてくる」
   └ 具体的な問いかけで終わってもよい
```

### Step 3. 文体チェック

- 敬語ベースの崩した話し口調か（「〜なんですよね」「〜ですけど」）
- 太字（`**`）・イコール（=）・矢印（→）が入っていないか
- 論理は「つまり」「だから」「でも」で繋いでいるか
- 括弧（）で本音・裏話・自虐が入っているか
- 誘導リンク・「詳しくは」・「noteで解説」が入っていないか
  - 例外：同テーマのnote記事と同日セットで出す場合のみ末尾1文のCTAを許可
  - OK：「note記事にまとめました。リンクはプロフィールから。」（話し口調1文）
  - NG：「詳しくはこちら」「↓から」「ぜひ読んでみてください」
- 促音が全体で2〜3箇所以内か
- 数字・製品仕様は公式情報で裏取りされているか
- 禁止語（絶対／誰でも／完全／最強 等）が入っていないか
- 同じ層の語尾が3文連続していないか（3連続したら体言止めか問いかけに崩す）
- 1行余白だけが延々続いていないか（2行余白の位置を変える）
- 全段落が2〜3文で揃っていないか（1文だけの段落を意図的に混ぜる）

**AIっぽさ検知ゲート（TEXTUAL_IDENTITY_SPEC §8）**
- [ ] フックが直近3本と同じ「型」になっていないか
- [ ] フックの具体フレーズが直近5本と被っていないか
- [ ] 締めが「いかがでしたか／ぜひ試して」系になっていないか
- [ ] 接続詞が「まず→次に→さらに→最後に」と几帳面に並んでいないか
- [ ] 文の長さが全部同じくらいで緩急が消えていないか
- [ ] 数字がいつも「3つ」になっていないか（2つ・5つも使う）
- [ ] 三点リーダー（…）の位置・回数が毎回同じパターンでないか
- [ ] 同一単語を1記事で3回以上使っていないか
- [ ] 今日の縛り（エンジン3）が反映されているか
- [ ] 全体が綺麗にまとまりすぎて人間の「引っかかり・脱線」が消えていないか

### Step 4. 品質ゲート（最終確認）

```
[ ] 読者の認識が変わる内容か（手順・操作説明になっていないか）
[ ] 一次情報（実体験・失敗談）が含まれているか
[ ] 個人・勤務先が特定されるリスクがないか
[ ] 本業の社内事例・実データが含まれていないか
[ ] 旧ブランド名が含まれていないか
[ ] 成果保証・収益保証を示唆する表現がないか
[ ] AIっぽさ検知ゲートを全項目クリアしているか
[ ] 今日の縛り（エンジン3）が反映されているか
```

### Step 5. ログに追記

`operations/article-log.md` のX長文記事ログに今回使った要素を追記する。
次回記事のエンジン2ロック判定に使う。

## 禁止事項（このスキル固有）

- 実行手順・操作手順を書く（noteに委ねる）
- 「詳しくはnoteで」「リンクから確認」などの誘導
- 太字・矢印・箇条書きの多用（散文で書く）
- 複数のテーマを一投稿に詰め込む（1投稿＝1転換点）
