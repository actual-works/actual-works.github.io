# prompts/note-writer.md — note記事 生成プロンプト

> スキル名：`actualworks-note-writer`
> 用途：ACTUAL WORKS note記事の生成（実行手順・詳細ガイド）
> 最終更新：2026-06-29

---

## このスキルの目的

読者が**実際に一つの業務を動かせる状態**にするnote記事を生成する。
「何をどの順番でやるか・どう判断するか・失敗したらどうするか」を渡す。
考え方・マインドの話はX長文記事に委ねる。

---

## 入力（必須）

```
テーマ       ：記事で扱う業務・手順・型
対象読者層   ：A（未着手）/ B（未設計）/ C（未仕組み化）
対応するX記事：このnoteと対になるX長文記事のテーマ（あれば）
前提条件     ：読者が持っておくべきもの・知識・環境
成果物定義   ：記事を読み終えた読者が「できるようになること」を一文で
```

---

## 生成手順

### Step 1. 成果物を先に定義する

記事を書く前に以下を確定する。

```
読者の現状（As-Is）：今できていないこと・困っていること
記事後の状態（To-Be）：記事を読んで実行した後にできること
合格基準：「これができたらTo-Beに達した」と判断できる具体的な状態
```

To-Beと合格基準が言えない場合は、テーマを絞り直す。

### Step 2. 構成を組む

```
1. 冒頭（何が手に入るか・誰向けか）
   └ 対象読者・前提条件・この記事でできるようになること
   └ 対象外の読者も明示する（適用範囲を絞る）

2. 効く条件・前提
   └ この手順が機能する条件
   └ 逆に機能しないケースも書く

3. 実行手順（番号付き・操作レベルで具体的に）
   └ 各ステップ：何をするか → どうやるか → 何を確認するか
   └ 判断が必要な箇所は「ここで人間が判断する」と明示
   └ 変数（状況によって変わるもの）と固定ルール（変えないもの）を分ける

4. テンプレート・記入例
   └ コピペして使える形式（【】で差し替え箇所を示す）
   └ 記入例（before/after）があるとなお良い

5. 合格基準
   └ 「これができたらOK」を具体的に書く
   └ 数値や状態で判断できる形にする

6. 失敗パターンと回避策
   └ よくある失敗3〜5パターン
   └ 各パターン：症状 → 原因 → 修正方法

7. チェックリスト
   └ 実行前・実行中・実行後の確認項目

8. 次の一手
   └ この記事の先に進む読者への案内（内部リンクで委譲）

9. 署名クローザー
   └ AIは道具だ。設計なしに、道具は機能しない。
```

### Step 3. 各ステップの具体度チェック

各実行手順ステップに対して確認する：
- 「〜する」だけで終わっていないか（**何を・どのように・何を確認するか**まで書く）
- 読者が一人で再現できる粒度か
- 曖昧な指示（「適切に」「うまく」「なんとなく」）が含まれていないか

### Step 4. 文体チェック

- 一人称は「自分」か
- 文末は「〜んです」「〜と思っています」基調か
- 煽り・誇張・「稼げる」断定がないか
- 署名クローザーが末尾にあるか

### Step 5. 品質ゲート（最終確認）

```
[ ] 成果物定義（As-Is / To-Be / 合格基準）が明確か
[ ] 読者が一人で実行・再現できる粒度か
[ ] テンプレート・チェックリスト・合格基準のうち最低1つあるか
[ ] 失敗パターンと修正方法があるか
[ ] 既出note記事と重複していないか（あれば内部リンクで委譲）
[ ] 変化しやすい情報（AIモデル・料金・機能）の最新性を確認したか
[ ] 個人・勤務先が特定されるリスクがないか
[ ] 本業の社内事例・実データが含まれていないか
[ ] 旧ブランド名が含まれていないか
[ ] 成果保証・収益保証を示唆する表現がないか
[ ] 署名クローザーが末尾にあるか
```

---

## 出力形式

```
【テーマ】
【対象読者層】A / B / C
【As-Is】
【To-Be】
【合格基準】
【タイトル】本文を書いた後、内容を見て読者の注目を引くタイトルを作成する
  - 記事で手に入るものと対象読者の課題感が伝わるタイトル
  - 「——」で副題をつなぐ形もOK（手順書・実装ガイド型の場合は特に有効）

---

（本文）

---

【ステップ具体度チェック結果】
【品質ゲート結果】
```

---

## 禁止事項（このスキル固有）

- 手順なしの考え方・マインド解説（X長文記事に委ねる）
- 「詳しくはXで」などの外部誘導
- 合格基準のない手順（「やってみてください」で終わる）
- 曖昧な指示・「なんとなくうまくいく」系の表現
- 同一統計・同一テンプレートの使い回し
- AI出力を未検証のままテンプレートとして掲載
