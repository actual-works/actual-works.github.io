# prompts/theme-research.md — テーマ収集ワークフロー

> 記事テーマを10個収集し `operations/theme-pool.md` の未使用プールに追記するまでの手順。
> 収集はWeb検索を使い、複数のプラットフォームから幅広く拾う。
> 最終更新：2026-06-29

---

## 実行タイミング

- 初回：最初の記事作成前に必ず実行する
- 補充：`theme-pool.md` の未使用プールが0になったとき
- 随時：「面白いテーマを見つけた」と感じたときに単発で追加してもよい（その場合も重複チェックを行う）

---

## Step 1：事前確認（重複チェックの準備）

`operations/theme-pool.md` を開き、以下を確認する。

```
[ ] 使用済みアーカイブの全テーマを把握した
[ ] 未使用プールに残っているテーマを把握した（0件であることを確認）
[ ] 収集バッチ番号を確認した（今回は第〇バッチ）
```

---

## Step 2：Web検索によるテーマ収集

以下の**収集先リスト**から複数のプラットフォームを横断して検索する。
1回の収集で同じプラットフォームに偏らないよう、最低4〜5か所から取得する。

### 収集先リスト（優先度順）

**【SNS・コミュニティ】**
- X（旧Twitter）：ターゲット層のツイート・リプライ・スペース。「AI 困った」「AI 使えない」「プロンプト」などの検索
- note：ターゲット層が書いた記事のコメント・スキの多い記事のタイトル傾向
- Reddit（r/productivity / r/AItools / r/ChatGPT）：英語圏の悩み・質問スレッド
- Quora / Yahoo!知恵袋：「AIを使いたいけど〜」系の質問
- LinkedIn：管理職・会社員層のAI活用に関する投稿・コメント

**【Q&Aサイト・フォーラム】**
- ChatGPT / Claude / Gemini の公式コミュニティフォーラム
- Zenn / Qiita：非エンジニア向けのAI活用記事のコメント欄
- Teratail・Stack Overflow（日本語版）：実務でつまずいている質問

**【検索エンジン】**
- Googleサジェスト：「AI 業務」「プロンプト 書けない」「ChatGPT 使い方」などで出てくる関連キーワード
- Googleトレンド：直近3〜6ヶ月の上昇キーワード
- Yahoo!検索のサジェスト

**【メディア・ニュース】**
- ITmedia / TechCrunch Japan / Impress Watch：AIツールの新機能・企業導入事例記事のコメント欄
- NHK / 日経ビジネス：AI活用の社会的課題・現場の声
- 海外（The Verge / Wired / MIT Technology Review）：日本語圏でまだ議論されていないテーマの先行把握

**【書籍・教育プラットフォーム】**
- Amazonレビュー：AI活用・仕事術・業務効率化カテゴリの本のレビューで「できなかったこと」「期待と違った」系のコメント
- Udemy / Schoo：AI関連講座のレビューと受講者の質問

---

## Step 3：収集プロンプト（AIに渡す）

以下を検索AIまたはリサーチAI（Grok・Perplexity等）に渡す。

```
あなたはコンテンツリサーチャーです。
以下の条件で、記事テーマの候補を10個収集してください。

【対象読者】
日本の30〜50代のビジネスパーソン（会社員・管理職・非エンジニア・中小経営者・
個人事業主・副業会社員・社内AI推進担当）。
AIに関心はあるが、何から始めるか、どう業務へ組み込むか、
どう品質を判断するかが分からない人。

【収集先】
以下のプラットフォームを横断して検索する（最低4〜5か所から取得）：
X（旧Twitter）、note、Reddit、Yahoo!知恵袋、Googleサジェスト、
Googleトレンド、ITmedia、Amazon レビュー（AI活用・仕事術カテゴリ）、
ChatGPT/Claude/Gemini の公式コミュニティフォーラム

【収集のポイント】
- 「AIを使おうとして困ったこと・詰まったこと・諦めたこと」を探す
- 「AIを使ってみたが成果が出なかった理由」を探す
- 「AIを使えている人と使えていない人の違い」を探す
- 「30〜50代の非エンジニアが感じるAIへの不安・誤解・壁」を探す
- 「管理職・経営者がAI導入で直面している現実的な課題」を探す
- 英語圏の議論で日本語圏にまだ来ていないテーマも拾う

【除外条件】
以下のテーマは除外する（既存記事と被るため）：
- AIで副業する前に本業を訓練場にする
- AIを使っているのに変わった気がしない
- 最初の1業務の選び方と実装
- AI時代の5つのソフトスキル
- AIを使う前のデータ整理
- 最新AIを追いかけても伸びない・型に投資する
- 組織の見えない依存関係を洗い出す
- チームにAIを組み込む実装手順
- 繰り返し業務のAI設計型
- AI活用はプロンプトより前で決まる
- 神プロンプト収集をやめ3つの土台を設計する
- Gemini/Claude/ChatGPT の業務設計マニュアル
- マニュアル化できない業務をAIに渡す設計手順
- AI指示書ライブラリで業務を資産に変える
- AIを初めて使う日のための手順書
- AIを「使わない半分」の地図

【出力形式】
テーマ候補を10個、以下の形式で出力する：

1. テーマ（一文で）
   - 収集元プラットフォーム：
   - 読者の悩みの核心（一文）：
   - X長文向きか・note向きか・両方か：
   - なぜ今このテーマが刺さるか（一文）：

（以下2〜10も同形式）
```

---

## Step 4：テーマの評価・絞り込み

収集した10候補を以下の基準で評価し、低評価のものは差し替えて10個に整える。

### 採用基準（すべて満たすもの）

```
[ ] ターゲット層（30〜50代・非エンジニア・会社員）の実際の悩みから来ているか
[ ] 「なぜ・どう考えるか」（X長文）か「何をどうやるか」（note）が書けるか
[ ] 既存24記事・使用済みアーカイブと核心メッセージが被っていないか
[ ] 公開情報＋個人環境での検証を根拠に書けるか（本業機密・出所不明情報が不要か）
[ ] ACTUAL WORKS のブランドの芯「AIは道具。設計なしに道具は機能しない」と
    接続できるか
```

### 却下基準（1つでも当てはまれば除外）

```
[ ] AIニュース・モデル性能ランキングが主題になっている
[ ] 「〇〇で稼ぐ」「月収〇万円」が前提になっている
[ ] 本業の社内事例・機密情報がないと書けない
[ ] 既存記事と核心メッセージが同一（内部リンクで済むレベル）
[ ] ACTUAL WORKS の読者層（30〜50代の実務家）に刺さらない
```

---

## Step 5：theme-pool.md への追記

評価を通過した10テーマを `operations/theme-pool.md` の未使用プールに追記する。

**追記フォーマット：**
```
[バッチ番号-連番] テーマ（一文） | 収集元プラットフォーム | 収集日 | 向き（X/note/両方）
```

収集バッチ履歴にも記録する：
```
| バッチ番号 | 収集日 | 収集数 | 収集元プラットフォーム | 担当AI |
```

---

## Step 6：テーマのランダム選定

記事作成に入るときは、未使用プールから以下の方法でランダムに選ぶ。

```
未使用テーマ数をN（例：10）として、1〜N の乱数を1つ生成し、
対応する番号のテーマを選定する。

選定後：
1. そのテーマを未使用プールから削除する
2. theme-pool.md のランダム選定ログに記録する
3. 記事公開後に使用済みアーカイブへ移動する
```

---

## 収集サイクルの全体図

```
[未使用プールが0]
      ↓
Step 1：使用済みアーカイブを確認（重複防止）
      ↓
Step 2-3：Web検索で10テーマを収集
      ↓
Step 4：採用・却下基準で評価・絞り込み
      ↓
Step 5：theme-pool.md に追記
      ↓
[未使用プールに10テーマ]
      ↓
Step 6：乱数でランダム選定 → 記事作成へ
      ↓
[記事公開] → 使用済みアーカイブへ移動
      ↓
[未使用プールが0になったら最初に戻る]
```
