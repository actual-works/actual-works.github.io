# prompts/x-longform-workflow.md — X長文記事 制作ワークフロー

> X長文記事を作るときの5ステップ実行手順。
> 各ステップで使うAIとプロンプトを定義する。
> 最終更新：2026-06-29

---

## 全体の流れ

```
Step 1（Grok）  ：トレンドリサーチ → バズ記事の切り口を把握
Step 2（Grok）  ：見出し（構成案）を3パターン作成
Step 3（Grok）  ：本文ドラフト（5,000字以上）を生成
Step 4（Claude）：ACTUAL WORKSコンセプトに沿ってリライト
Step 5（ChatGPT）：記事に入れる画像・図解の指定と生成
```

---

## Step 1：Grokでトレンドリサーチ

```
あなたはX（旧Twitter）のトレンドリサーチャーです。
直近でバズっている長文記事（Article）を、日本国内と海外の両方から探してください。

【条件】
- 直近1〜3ヶ月以内に投稿された記事
- インプレッション・いいね・リポストが多いもの
- ジャンル：（書きたい領域を指定する）

【各記事について抽出する】
- 記事のタイトルと冒頭の3行
- 推定インプレッション数・エンゲージメント
- 何がフックになって伸びたのか（テーマ・切り口・感情）の分析
- 自分が書くとしたら、どの切り口を真似できそうか

【出力】
- 国内5本・海外5本をリストアップ
- それぞれ「なぜバズったか」を1〜2行で添える
- 最後に、今の自分が書くなら狙い目のテーマを3つ提案する
```

---

## Step 2：Grokで見出し（構成案）を作成

```
あなたはX（旧Twitter）の長文記事を書くプロのライターです。
これから書く記事の「見出し（構成案）」だけを作ってください。本文はまだ書きません。

【テーマ】
（ここに書きたいテーマを入れる）

【素材】
- 過去のセッション（会話履歴）を読み、記事に使える一次情報
  （自分の経験・数字・失敗・データ・考え方）を箇条書きで抽出してから構成を組む

【見出しのルール】
- 見出しはキャッチコピー。「〇〇まとめ」「なぜ〇〇か」のような説明文はNG
- 名詞で終わる、自然で素直な言い回しにする
- 数字を盛らない（「7選」と書くなら、本文で本当に7個出す）
- 読者が「おっ」と思って、次を読みたくなるかどうかで判断する

【構成の型】
1. 冒頭：結論かインパクトを即出し
2. 序文：背景を軽く
3. 本編：気づき・マインドセット → 仕組み → 具体的なやり方
4. 締め：読者が今日から変えられる「認識」または「次の一手の宣言」

【出力】
- 見出しを上から順に並べる
- 各見出しの下に、何を書くかを1行メモで添える
- 3パターン出して、選べるようにする
```

## Step 3：Grokで本文ドラフトを生成

```
あなたはX（旧Twitter）の長文記事を書くプロのライターです。
さきほど作った見出しに沿って、本文を書いてください。

【素材として読み込むもの】
1. このあとに貼るX記事ナレッジ（書き方のルール）
2. 過去のセッション（会話履歴）の一次情報（自分の経験・数字・失敗・データ・考え方）を最優先で使う

■ 文字数
- 目標：5,000文字以上
- 優先順位：①読者への気づき・マインドセットの展開を先に厚くする
            ②それでも不足する部分を実例・具体例で埋める
- 文字数のためだけの水増しはしない

■ 文体
- 敬語ベースだが崩す（「〜なんですよね」「〜ですけど」）
- 太字は使わない
- 文頭の「で、」は使わない（「それで、」にする）
- イコール記号は使わない（「つまり」「だから」で繋ぐ）
- 「AI」と書ける場面でも具体名（Claude、Cursor、ChatGPT）を出す
- 括弧（）で本音・裏話感を出す

■ 一次情報
- 自分にしか書けない経験・数字・失敗談を必ず入れる
- ネットで拾える情報の寄せ集めにしない

■ 離脱させないテンポ
- 真面目な解説の途中に、急にふざけた1文を入れる
- 短文で脳に余白を入れる（「はい。」を毎回使わない）
- 読者が「え？」と思う前に、自分から先回りでツッコむ
- 促音は記事テーマに合わせて都度作る。1記事2箇所まで

■ 説得力
- 数字で現実を見せてから、正直な現在地に落とす
- 数字は対比で見せる（時間短縮の矢印表現「2時間→10分」はNG）
- 失敗談を必ず入れる。他人は笑わず、自分を笑う

■ 構造・テーマの反復防止
- 本文を書く前に、直近2本の記事について以下5点を1行でメモする
  1. フックのタイプ（どんな場面・感情から入ったか）
  2. 核心メッセージ（記事が言いたいこと1行）
  3. 本文で紹介したフレームワーク・手順の名前
  4. 読者への主な問いかけの内容
  5. 締めのCTAアクション（読者に今日やってほしいこと）
- 上記5点のうち2点以上が今回と被る場合は、テーマを変えるか別の切り口を見つける
- 連続する記事で同じ具体例（ツール名・プロンプト文言・数字）を繰り返さない

■ 表現の反復防止（使わない固定表現）
- 「これ、普通に起きます」
- 「派手ではないです」
- 「まだ全然です」
- 「終わってる」
- 「人間なので」
- 「きれいなズレ」
- 「クッッッソ地味」
- 「はい。」だけの間
- 「〇〇した。〇〇した。〇〇した。」のような三連短文
- 「仕組み化できているんでしょう。……まだ全然です。」のような自虐の定型展開

■ やってはいけないこと
- ですます調だけで最後まで書く
- 太字の多用
- 変なところで改行する
- 「〇〇って思った人、全然違います」のようなAIっぽい語りかけ
- 根拠のない断言

【書き方の手順】
0. 直近2本の記事を読み、フック・核心メッセージ・フレームワーク・CTAを1行でメモする
1. 過去セッションから一次情報を抽出する
2. 直近記事で使った決まり文句を抽出し、今回使わない表現リストを作る
3. 共感フック／自己ツッコミ／短文の間／促音表現／締めの言い方について、それぞれ3案を内部で作る
4. 見出しごとに本文を書く
5. 冒頭は最後にもう一度練り直す（最初の3行で「え？」を作る）
6. 出力前に、反復防止リストと直近記事を照合し、似た表現を差し替える
```

## Step 4：ClaudeでACTUAL WORKSコンセプトに沿ってリライト

Grokの出力をそのままClaudeに貼り付けて、以下のプロンプトを実行する。

```
添付はXの長文記事のドラフトです。
これを私のActual Worksコンセプトに当てはめてリライトしてください。
あわせて、直近記事と似た言い回しを検出し、同じ役割の文でも
前後文に合わせて別表現に差し替えてください。

特に以下の固定表現は使わないでください：
「これ、普通に起きます」「派手ではないです」「まだ全然です」
「終わってる」「人間なので」「きれいなズレ」「クッッッソ地味」
「はい。」だけの間、三連短文、自虐の定型展開
```

リライト時にClaudeが参照するもの：
- `owner.md`（ブランドの芯・禁則）
- `TEXTUAL_IDENTITY_SPEC_v3.0.md`（文体・アンチマンネリエンジン）
- `operations/article-log.md`（直近記事の使用済み要素ログ）

## Step 5：ChatGPTで画像・図解を指定・生成

```
記事に入れる画像を用意してください。

【やること】
1. 数字の成果（インプ数・リスト獲得・売上画面など）はスクショで見せる
2. 仕組みやフローは図解で可視化する（HTMLで作ってスクショして画像化）
   - 白背景に青アクセント（#1568F0）の図解が基本
3. ツールの操作画面はスクショして、注目させたい箇所を赤枠で囲む

【出力】
- どの見出しの、どこに、どんな画像を入れるかを指定する
- 図解はHTMLで作って、スクショしやすい状態に整える

※X記事への実際の貼り付け作業は手動で行う
```

## 各ステップの判断基準

| ステップ | 完了の判断 |
|---|---|
| Step 1 | 狙い目テーマ3案が出て、自分の一次情報と紐づけられる |
| Step 2 | 見出し3パターンのうち1つを選び、構成が納得できる |
| Step 3 | 5,000字以上、反復防止リストをクリア |
| Step 4 | 禁則表現なし・ブランドの芯が通っている・文体ログに追記 |
| Step 5 | 各見出しに対応する画像配置が決まっている |
