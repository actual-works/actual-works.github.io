## 本文

### この記事で何が手に入るか

AIに何かを作らせるたびに「なんか違う気がする」と感じて、プロンプトを直し続けている状態から抜け出す手順書です。

読み終えた後、あなたは以下のことができるようになります。

- AIの出力を「合格/不合格」で判断するための基準を、1業務分で定義できる
- 「なんか違う」を「ここが違う」に言語化できる
- プロンプトの修正が収束する（「終わり」が分かるようになる）
- 合格基準シートを使って、他の業務にも同じ手順を展開できる

---

### この手順が効く条件・前提

**対象読者**

ChatGPT・Claude・Gemini などのAIツールをすでに使っていて、「出力の品質が安定しない」「毎回修正を繰り返している」「正しいかどうかが判断できない」と感じているビジネスパーソン（B層）。

**前提条件**

- いずれかのAIツールのアカウントがある（無料版で可）
- 対象業務を1つ決めておく（何でも可、毎日やっている繰り返し作業が最適）
- 作業時間：初回60分、2回目以降は10〜15分

**この手順が「効かない」ケース**

- まだAIを一度も使ったことがない（まずは `n8d369c9e739a` の実装ガイドから始めてください）
- 法的判断・医療診断・財務処理など、人間の専門知識による最終確認が必須の業務（合格基準を定義しても、出力をそのまま使用することは推奨しません）
- 「完璧な出力」を求めている（この手順は「使える出力」を得るための設計です）

---

### Block 1：実装手順

> 全体の流れ（なぜこの順番か）

多くの人がプロンプト修正の無限ループに入る理由は、「終わり」を決める前に使い始めているからです。この手順は「合格基準を先に決める → 出力を判定する → 必要な分だけ直す」の順で設計しています。先にゴールを決めてから出力を見るだけで、修正が収束します。

---

**Step 1：対象業務の「完成形」を3要素で定義する**（目安時間：20分）

やること：
- 対象業務を1つ選ぶ（毎日繰り返している定型作業が最適）
- 以下の3要素を書き出す

```
【対象業務】：（例：週次レポートのサマリー作成）

① 用途：誰が・何のために使うか
   （例：上司が月曜の朝に確認する。先週の進捗と課題を5分で把握するため）

② 必須の要素：出力に必ず入っていなければならないこと
   （例：先週の成果3点・今週の優先タスク・懸念事項）

③ 排除条件：出力に入っていてはいけないこと
   （例：個人名・社内固有略語・推測を事実として書くこと）
```

判断ポイント：③の排除条件が書けない場合は、①の「用途」に戻ってください。「何のために使うか」が明確であれば、何が邪魔かも分かるはずです。

躓きポイントと対処：
- 「対象業務が決められない」→ 直近1週間で3回以上やった作業を選んでください。迷ったら「メール返信」か「議事録まとめ」が最も試しやすいです。
- 「完成形がイメージできない」→ 自分が過去に作った、「これは上手くできた」と感じた成果物を1つ引っ張り出してください。それが合格基準のベースになります。

---

**Step 2：合格基準を「判定できる形」に変換する**（目安時間：20分）

やること：
- Step 1で書いた3要素を、「チェックできる文」に変換する
- 以下のフォーマットに書き写す

合格判定シートのフォーマット（コピペ可）：

```
【業務名】：

■ 必須チェック（1つでも✕なら修正）
[ ] 【必須要素①】が含まれているか
[ ] 【必須要素②】が含まれているか
[ ] 【必須要素③】が含まれているか

■ 排除チェック（1つでも✕なら修正）
[ ] 【排除条件①】が含まれていないか
[ ] 【排除条件②】が含まれていないか

■ 全体品質チェック（任意・慣れたら追加）
[ ] 用途（誰が・何のために）に合った内容か
[ ] 読む人が5分以内で要点を把握できるか
[ ] 事実と推測が混在していないか

■ この出力の判定：合格 / 要修正（修正箇所：　　　　）
```

判断ポイント：「判定できる文」かどうかの確認方法は、第三者に見せて同じ結論になるかです。「なんとなく良い」「クオリティが高い」は判定できる文ではありません。「〇〇が含まれているか」「〇〇という単語が使われていないか」のように、見れば分かる形にしてください。

躓きポイントと対処：
- 「基準が曖昧になってしまう」→ 「良い・悪い」は不可。「ある・ない」「できている・できていない」で書き直してください。
- 「基準が多すぎて複雑になる」→ 必須チェックは最大5項目まで。まず「これがなければ使えない」だけを残してください。

---

**Step 3：AIに出力させ、シートで判定する**（目安時間：20分）

やること：
- AIに対象業務を指示して出力させる（プロンプトはこの段階ではラフでよい）
- Step 2の合格判定シートを見ながら、各項目をチェックする
- 「合格」か「要修正（修正箇所：〇〇）」を記録する

この段階での目標：「合格/要修正」の判定が言語化できること。感覚ではなく、シートの項目に照らして「ここが足りない」と指摘できる状態にする。

躓きポイントと対処：
- 「シートを見ても判断できない」→ 必須チェックの文が「判定できる形」になっていない可能性があります。Step 2に戻り、「ある・ない」で答えられる形に書き直してください。
- 「全部✓になったのに何か違う気がする」→ 「違う気がする」の正体を言語化してみてください。言語化できたら、それが抜けていた合格基準です。シートに追加します。

### Block 2：テンプレート集

**テンプレート：合格判定シート（記入例付き）**

用途：AI出力を業務で使えるかどうか判定するシート
使い方：Step 2で作成したシートを使い、AIの出力が出るたびに埋める

```
【業務名】：週次レポートのサマリー作成

■ 必須チェック（1つでも✕なら修正）
[ ] 先週の成果が3点以上含まれているか
[ ] 今週の優先タスクが明記されているか
[ ] 懸念事項または課題が1点以上含まれているか

■ 排除チェック（1つでも✕なら修正）
[ ] 個人名が含まれていないか
[ ] 社内固有略語が使われていないか（上司が文脈なしで読むため）
[ ] 推測を事実として断言している箇所がないか

■ 全体品質チェック
[ ] 月曜の朝に5分で読める分量（300〜500字程度）か
[ ] 先週から今週への流れが分かるか
[ ] 事実ベースの記述になっているか

■ この出力の判定：要修正
修正箇所：「懸念事項」の項目がない。追加でプロンプトに「懸念点を1点含める」を指定する。
```

用途：どの合格基準が満たされなかったか → プロンプトをどう直したかを記録する

```
【日付】：
【業務名】：
【満たされなかった合格基準】：
【プロンプトの修正内容】：
【修正後の判定】：合格 / 要修正
```

記入例：
```
【日付】：2026-06-30
【業務名】：週次レポートのサマリー作成
【満たされなかった合格基準】：懸念事項が含まれていなかった
【プロンプトの修正内容】：末尾に「今週の懸念点または課題を1点、事実ベースで追記してください」を追加
【修正後の判定】：合格
```

### Block 3：計測・検証

**合格基準**

この記事の手順が機能しているかは、以下で判断してください。

- 合格：合格判定シートを使って「合格」か「ここを直す」かが言語化できる
- 要改善：シートを埋めても「なんか違う気がする」が残る → Step 2に戻り、「違う気がする」を項目として追加する
- 見直し：業務そのものの定義が曖昧 → まず業務の「誰が・何のために使うか」を固める

**計測フォーマット**

| 項目 | 計測方法 | 判断基準 |
|---|---|---|
| 判定できたか | 「合格/要修正」を言語化できたか | 言語化できた＝合格 |
| 修正が収束したか | 修正回数が3回以内で合格になったか | 3回以内＝機能している |
| 次の業務に展開できるか | 同じシートの構造を別業務で使えるか | 使えた＝定着した |

### Block 4：失敗パターンと回避策

**パターン 1：基準が「良し悪し」の感想になっている**

症状：シートに「クオリティが高いか」「読みやすいか」と書いたが、結局毎回「なんか違う」が出る。
原因：「ある・ない」で判定できない文が混じっている。感想は基準にならない。
修正方法：「クオリティが高いか」→「300字以内に収まっているか」「箇条書き3点以内か」のように、見れば分かる形に書き直す。

---

**パターン 2：基準が多すぎてシートを使わなくなる**

症状：最初は丁寧に作ったが、10項目以上になり確認が面倒になって使わなくなった。
原因：「あったらいい基準」と「なければ使えない基準」を混在させてしまっている。
修正方法：必須チェックを最大5項目に絞る。「なければ使えない」だけを必須に残し、残りは全体品質チェック（任意）に移動する。

---

**パターン 3：合格になったのに上司や読者からフィードバックが来る**

症状：シートでは合格のはずなのに「違う」と言われた。
原因：合格基準が自分視点だけで定義されている。「誰が使うか」の視点が抜けている。
修正方法：シートの「用途」欄（誰が・何のために）を再確認する。可能であれば、上司や読者に「どうなっていれば使いやすいか」を1回だけ聞いてシートに反映する。

---

**パターン 4：毎回プロンプトをゼロから作り直している**

症状：合格基準は定義できたが、毎回プロンプトを一から書いているため時間がかかる。
原因：プロンプトと合格基準が紐づいていない。修正ログが残っていない。
修正方法：「プロンプト修正ログ」テンプレートを使い始める。合格した時点のプロンプトを保存し、次回以降はそこから修正する形にする。プロンプトライブラリの作り方は `n150a71f698df` で詳しく説明しています。
